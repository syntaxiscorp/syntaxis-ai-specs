# US-011: Validación de integridad jerárquica post-carga

## Historia
Como **supervisor de obra**, quiero que **el sistema valide automáticamente la integridad del árbol después de una carga masiva**, para **garantizar que no queden nodos huérfanos ni relaciones rotas tras procesar el archivo Excel**.

Épica 3: ProcesMassive & Data Sync

- **MoSCoW**: Could

## Estimación
- **Story Points (Fibonacci)**: 5
- **T-Shirt Size**: M
- **Planning Poker Rationale**: Complejidad media. Requiere implementar un algoritmo de validación que verifique que todos los nodos tengan un padre válido, que no haya ciclos, y que la raíz del árbol exista. El equipo convergería en 5 porque la lógica es conocida (DFS para detección de ciclos) pero debe integrarse con el flujo de carga masiva.

## Caso de Uso

### Caso de Uso: Validación de integridad del árbol post-carga masiva
- **Actores**: Sistema de validación (automático)
- **Precondiciones**: Se ha completado una operación de carga masiva (US-010) o cualquier modificación batch de nodos.
- **Flujo Principal**:
  1. El sistema recibe la señal de "carga masiva completada"
  2. El sistema ejecuta el validador de integridad del árbol
  3. Para cada nodo, verifica que su padre exista en el sistema
  4. Para cada nodo, verifica que no haya referencias circulares (A→B→A)
  5. Verifica que exista al menos un nodo raíz (sin padre)
  6. Genera un reporte de validación
- **Flujos Alternativos**: Si se detectan nodos huérfanos, el sistema intenta asignarlos al nodo raíz por defecto y reporta la acción como advertencia.
- **Postcondiciones**: Se genera un reporte de validación con el estado del árbol (íntegro o con incidencias)

## Criterios de Aceptación (BDD)

### Feature: Validación de integridad jerárquica post-carga

#### Escenario 1: Árbol íntegro después de carga
```gherkin
Dado que se ha completado una carga masiva de 200 nodos
  Y todos los nodos tienen padreId válido y existente
  Y no hay ciclos en las referencias
Cuando se ejecuta la validación de integridad
Entonces el reporte indica "Árbol íntegro — 0 errores, 0 advertencias"
  Y no se requiere ninguna acción correctiva
```

#### Escenario 2: Nodos huérfanos detectados
```gherkin
Dado que se ha completado una carga masiva
  Y 5 nodos tienen padreId que no existe en el sistema
Cuando se ejecuta la validación de integridad
Entonces el reporte indica "5 nodos huérfanos detectados"
  Y los 5 nodos se reasignan automáticamente al nodo raíz
  Y se registra una advertencia por cada reasignación
```

#### Escenario 3: Ciclo detectado en la jerarquía
```gherkin
Dado que existe una relación cíclica: A → B → C → A
Cuando se ejecuta la validación de integridad
Entonces el reporte indica "Ciclo detectado: A → B → C → A"
  Y los nodos involucrados en el ciclo se marcan como "pendiente de revisión"
  Y la operación de carga no se completa hasta resolver el ciclo
```

#### Escenario 4: Sin nodo raíz
```gherkin
Dado que después de una carga masiva no existe ningún nodo sin padreId
Cuando se ejecuta la validación de integridad
Entonces el reporte indica "Error: No se encontró un nodo raíz en el árbol"
  Y la operación de carga se revierte
```
