## Estimación
- **Story Points (Fibonacci)**: 5

- **Planning Poker Rationale**: Complejidad media. Requiere implementar un algoritmo de validación que verifique que todos los nodos tengan un padre válido, que no haya ciclos, y que la raíz del árbol exista. El equipo convergería en 5 porque la lógica es conocida (DFS para detección de ciclos) pero debe integrarse con el flujo de carga masiva.

## Caso de Uso

### Caso de Uso: Validación de integridad del árbol post-carga masiva
- **Actores**: Sistema de validación (automático)
- **Precondiciones**: Se ha completado una operación de carga masiva (US-010) o cualquier modificación batch de nodos.
- **Flujo Principal**:
  1. El sistema recibe la señal de "carga masiva completada"
  2. El sistema ejecuta el validador de integridad del árbol
  3. Para cada nodo, verifica que su padre exista en el sistema
  4. Para cada nodo, verifica que no haya referencias circulares (A→B→A)
  5. Verifica que exista al menos un nodo raíz (sin padre)
  6. Genera un reporte de validación
- **Flujos Alternativos**: Si se detectan nodos huérfanos, el sistema intenta asignarlos al nodo raíz por defecto y reporta la acción como advertencia.
- **Postcondiciones**: Se genera un reporte de validación con el estado del árbol (íntegro o con incidencias)
